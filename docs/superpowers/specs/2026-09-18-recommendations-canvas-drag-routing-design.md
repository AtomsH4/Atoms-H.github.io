# 推荐页画布拖动与作品旋转交互设计

日期：2026-09-18

## 背景

当前推荐页把所有拖动都交给当前作品的旋转控制器：WebGL 版本使用 `PresentationControls`，CSS 降级版本使用 `useDragRotation`。因此拖动画布空白区域不会横向浏览作品，且现有浏览器测试还明确要求拖动后当前作品保持不变。

本设计以 [A24 交互参考站](https://a24.raviklaassens.com/) 的手势分流为准，替换此前“横向手势只旋转作品”的约定。本文件覆盖既有推荐页设计文档中的对应交互章节；内容模型、封面来源和海报视觉不变。

## 已确认目标

- 推荐页底层保持单一连续画布。
- 从画布空白处开始拖动时，整组作品在水平方向跟手移动。
- 从作品表面开始拖动时，只旋转命中的作品，不移动画布轨道。
- 松开空白拖动后保留有限惯性，并吸附到最近作品；吸附完成后更新当前作品及左上角信息。
- 移动端横向手势操作画布，纵向手势继续滚动页面。
- WebGL 与 CSS 降级版本遵循相同的命中规则和导航结果。
- 分类、作品内容、轨道位置与指针手势保持低耦合，未来增加作品不需要修改手势代码。

## 非目标

- 不增加缩放、相机平移、自动轮播或无限自由漫游。
- 不让一次拖动同时旋转作品和移动轨道。
- 不删除箭头、方向键或相邻作品点击等无障碍导航入口。
- 不改动推荐内容、封面来源或站点其他页面。

## 交互规则

### 空白区域拖动

1. 指针在画布背景命中面按下，手势进入 `pan` 模式并捕获该指针。
2. 尚未超过方向锁阈值时不移动内容。
3. 水平位移占主导时锁定为画布横移；轨道位置按指针位移实时更新，并限制最大跟手速度。
4. 垂直位移占主导时放弃画布手势，让浏览器继续纵向滚动。
5. 横向手势释放后，根据当前位置与末端速度计算短距离惯性，再吸附到最近作品中心。
6. 吸附目标确定后更新 `activeId`、URL hash、序号和元数据。一次大幅拖动可以跨过多个作品。
7. 轨道首尾采用循环索引，与现有箭头和键盘循环行为一致；视觉上只保留当前项及附近邻居。

### 作品表面拖动

1. 作品网格的 `pointerdown` 阻止事件继续传到背景命中面，手势进入 `rotate` 模式。
2. 指针位移只映射到该作品有限范围的 `rotateX` / `rotateY`。
3. 旋转期间轨道位置和 `activeId` 不变。
4. 释放后作品阻尼复位；减少动态效果时立即复位。
5. 未发生有效拖动的邻居作品点击仍切换当前作品。

### 光标与提示

- 空白画布使用 `grab` / `grabbing` 光标。
- 可旋转作品使用相同光标，但命中后的行为由射线结果决定。
- 底部只显示当前位置与总数，不展示拖动画布或拖动作品等操作说明。

## WebGL 架构

### `RecommendationExperience`

继续拥有 `filter` 与 `activeId`，并向舞台提供：

- 当前分类的作品数组；
- 当前作品 ID；
- `onSelect(id)`，作为吸附完成、箭头、键盘和点击邻居的统一选择入口。

它不保存逐帧拖动位置，避免高频 React 渲染。

### `RecommendationStage`

舞台新增独立的轨道控制器：

- `trackPosition`、`targetPosition`、`velocity` 存在 Three.js ref 中；
- `useFrame` 只在拖动、惯性或吸附未完成时更新；
- 作品位置由稳定的间距和循环索引计算，不再仅依赖离散 slot 跳变；
- 最近索引发生稳定变化时才调用 `onSelect`，避免每帧写 React 状态。

画布中增加位于作品后方的不可见背景命中面。背景命中面负责 `pan`；作品模型负责 `rotate` 并调用 `stopPropagation()`。因此两类交互由同一 Canvas 的射线命中结果分流，不需要覆盖 Canvas 的透明 DOM 层。

作品类型注册表只负责选择 `disc` 或 `book` 模型，不感知轨道拖动。轨道控制器只消费 ID 列表和固定间距，不感知内容分类或封面来源。

## CSS 降级架构

`RecommendationFallbackStage` 的根容器接收背景拖动；每个实体按钮阻止背景 `pointerdown`：

- 根容器通过 CSS 自定义属性控制轨道 `translateX`；
- 命中实体时继续使用纯函数旋转状态；
- 背景横移和吸附复用与 WebGL 相同的纯手势判定函数；
- 导航结果仍通过 `onSelect(id)` 回到父组件。

这样无 WebGL 环境不是另一套产品行为，只是不同的渲染实现。

## 共享手势状态

新增无渲染依赖的纯函数模块，职责限定为：

- 根据起点、当前位置和阈值判定 `pending | pan-x | release-to-scroll`；
- 计算受限的横向位移与释放速度；
- 根据轨道间距、当前索引和速度选择吸附索引；
- 规范化循环索引。

它不读取 DOM、不依赖 Three.js，也不拥有 `activeId`，从而可由 WebGL、CSS 降级和单元测试共同使用。

## 移动端与无障碍

- 舞台保留 `touch-action: pan-y`，浏览器原生处理纵向滚动。
- 只有确认水平手势后才阻止默认横向行为。
- 方向键、左右按钮和邻居点击继续工作，并与拖动吸附共享同一 `onSelect` 路径。
- 状态播报只在吸附到新作品后触发，不在拖动过程中连续播报。
- 减少动态效果时取消惯性，释放后直接吸附；作品旋转也直接复位。

## 测试与验收

### 单元测试

- 小位移保持 `pending`，不误触导航。
- 水平位移进入 `pan-x`，垂直位移交还页面滚动。
- 释放速度可以把吸附目标推进一个位置，但不能越过配置的安全上限。
- 循环索引在首尾正确归一化。
- 作品旋转状态与轨道横移状态互不修改。

### 组件测试

- CSS 舞台从空白处拖动会调用相邻或跨项 `onSelect`。
- 从当前作品开始拖动只改变旋转变量，不调用 `onSelect`。
- 邻居的短点击仍可选择作品。

### 浏览器测试

- 桌面端从 Canvas 空白处拖动后标题和 hash 切换，作品组跟手移动。
- 从当前 CD 或书籍表面拖动时 Canvas 画面变化，但标题和 hash 保持不变。
- 移动端水平拖动画布可切换作品，纵向拖动仍能滚动页面。
- 禁用 WebGL 后重复上述两种手势，结果一致。
- 箭头、键盘、分类切换、远程封面和无横向页面溢出回归测试继续通过。

## 风险与取舍

- Three.js 的作品事件必须阻止冒泡，否则一次作品旋转会同时触发背景横移；该边界需要浏览器回归测试。
- 轨道逐帧状态放在 ref 中可避免 React 抖动，但吸附完成时必须显式同步 `activeId`，否则元数据与画面可能短暂不一致。
- 移动端方向锁阈值过低会抢占滚动，过高则显得迟钝；使用统一的小阈值并以纵向滚动优先。
- 保留循环轨道与现有导航一致，但需要在视觉位置重映射时避免首尾跳变。
