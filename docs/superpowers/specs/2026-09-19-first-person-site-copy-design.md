# 第一人称个人信息文案设计

**状态：** 已确认，待用户审查
**日期：** 2026-09-19

## 目标

将网站中介绍 AtomsH4 的个人信息改为第一人称表达，使访客直接阅读“我”的经历、学习方向和项目实践。文案维持专业、克制，同时保留少量个人温度；不添加未经证实的履历或成果。

## 范围

- 首页：首屏简介与“关于 AtomsH4”入口文案。
- 关于页：页面导语及四项经历说明。
- 项目页：页面导语。
- 项目内容：六个项目条目的 `summary` 和 Markdown 正文。

项目名称、发布日期、标签、是否精选、仓库链接、项目归属（自有或 fork）与站外链接均保持不变。导航、页面结构、样式、数据模型和 URL 不在本次范围内。

## 现有实践与适用方式

站点由 Astro 页面输出首页、关于页和项目页，项目数据通过 `src/data/projects/*.md` 的 frontmatter 与正文维护。项目卡片和详情共用这些内容，因此在原有 Markdown 条目中同步修改摘要与正文即可保证两个展示位置一致，不需要改变内容集合定义或组件接口。

现有页面中混用了站点栏目标签（如 `Projects`、`Latest writing`）和中文描述。本次只改写指向站主个人身份、经历或行动的陈述；栏目名、按钮和状态文案不因“第一人称”要求而重命名。

## 文案规则

1. 用“我”作叙述主体，例如“我记录……”“我在……中学习与实践”。
2. 对自有项目使用主动、准确的说法，如“我正在将本站作为作品集入口持续完善”。
3. 对 fork 或学习仓库明确保留其性质，使用“我以 fork 仓库学习……”等表达，不暗示项目由我原创。
4. 技术名、产品名、项目名保持原拼写和大小写；不凭空补充岗位、团队、量化成果或技术细节。
5. 每条项目摘要保持单句、适合卡片阅读；正文可与摘要相同，维持当前项目内容的简洁结构。

## 拟定改写方向

| 位置 | 当前表达倾向 | 第一人称方向 |
| --- | --- | --- |
| 首页 | 概括地介绍站点记录内容 | “我在这里记录技术实践、零散思考和持续打磨的项目。” |
| 关于页 | 以旁观者描述经历 | “我围绕……学习和实践”“我用……探索开发效率” |
| 项目列表 | 概述所收录的项目 | “这里收录我正在实践、维护或学习的公开项目。” |
| 自有项目 | 描述项目的展示价值 | 交代我在项目中的目标与持续投入 |
| 学习 / fork 项目 | 旁观式项目说明 | 说明我通过该仓库进行学习，并保留 fork 标识 |

## 可访问性与错误处理

这次是静态展示文本的改写，不改变链接、交互、可访问名称、状态提示或错误处理。现有的 `aria-label` 和 `sr-only` 新标签页提示保持不变。

## 验证策略

- 通过内容检查逐项确认首页、关于页、项目页和六份项目 Markdown 都不再以第三方视角描述站主个人信息。
- 运行 `npm run check`，验证 Astro 页面与内容集合仍能通过类型和内容校验。
- 运行 `npm run build`，确认静态站点可构建，且共享项目内容同时能用于列表和详情路由。

## 验收标准

1. 所有站主个人信息均使用第一人称或明确的第一人称语境表达。
2. 语气兼具专业性和个人温度，保持简洁、可扫描。
3. 项目事实、链接、数据字段和项目归属没有变化；fork 条目仍清楚表明其学习性质。
4. 首页、关于页、项目列表和六份项目详情呈现一致的叙述视角。
5. Astro 类型检查和生产构建通过。
